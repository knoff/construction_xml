## Базовые принципы

1. **Актуальность.** Любое значимое изменение в коде сопровождаем обновлением документации.
2. **Единообразие.** Новые модули и API следуют описанным соглашениям.
3. **Прозрачность.** Описываем не только фактическую структуру, но и мотивы решений.
4. **Доступность.** Текст — на русском, с примерами и ссылками на исходники.

## Как вносить изменения

1. Обновите соответствующий Markdown-файл.
2. При необходимости добавьте схемы (PlantUML, Mermaid) или фрагменты кода.
3. Пройдите code-review. Изменения в документации рассматриваются вместе с кодом.
