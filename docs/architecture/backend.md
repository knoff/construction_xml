# Backend

## Обзор

Backend реализован на Python 3.11 с использованием FastAPI и SQLAlchemy. Код организован в несколько слоёв:

1. **Доменный слой (`app/services/domain`)** — бизнес-логика и агрегирование данных.
2. **Инфраструктурный слой (`app/services/infrastructure`)** — работа с внешними сервисами и хранилищами.
3. **API-слой (`app/api/http`, `app/api/routes`)** — обработка HTTP-запросов, сериализация и авторизация.
4. **DTO (`app/api/dto`)** — модели обмена данными между API и клиентом.

Связь слоёв однонаправленная: API → доменный слой → инфраструктура. Доменный слой не зависит от FastAPI, инфраструктура не знает о DTO.

## Доменный слой

- Разбит по предметным областям: `schemas`, `documents`, `document_versions`, `files`, `objects`, `sign`, `value_links`.
- Каждый пакет содержит `service.py` с публичным интерфейсом и `__init__.py`, экспортирующим основные классы/исключения.
- Дополнительные модули:
  - `schemas/internal.py` — разбор XSD, вспомогательные модели.
  - `_tmp/` — временные реализации, которые подлежат миграции.
- Правила:
  - Все зависимости инжектируются через параметры методов, без глобальных синглтонов.
  - Исключения оформляются в пакетах `exceptions.py` и пробрасываются наружу.
  - Домен не обращается к FastAPI, SQLAlchemy Session передаётся сверху.

## Инфраструктурный слой

- Пакет `app/services/infrastructure` хранит адаптеры к базе данных, MinIO, внешним API.
- Здесь находятся низкоуровневые реализации для доменных сервисов.
- Правила:
  - Не использовать FastAPI Request/Response.
  - Все функции принимают Session и простые аргументы.
  - Возвращаются словари/датаклассы, совместимые с доменными моделями.

## API-слой

- Пакет `app/api/http` содержит FastAPI-роутеры.
  - Внутри — директории по областям (`documents`, `value_links`, и т.д.).
  - Каждый модуль разделён на `router.py`, `dependencies.py`, `legacy.py` (при необходимости).
- Пакет `app/api/routes` агрегирует роутеры и пробрасывает их в приложение.
- Роутеры используют DTO для сериализации и доменные сервисы для логики.
- Правила:
  - Все ответы оформлять через Pydantic DTO.
  - Ошибки пробрасывать как `HTTPException` с кодами и подробностями.
  - Маршруты группировать по версиям и префиксам.

## DTO

- Расположены в `app/api/dto`.
- Используют Pydantic v1, поля именуются в snake_case.
- Для избежания конфликтов с Pydantic-приватными полями используем алиасы (`schema_` → `schema`).
- DTO не импортируют доменные сервисы и не содержат бизнес-логики.

## Соглашения по файлам

- `__init__.py` экспортирует публичные классы и функции, чтобы импортировать через `from app.services.domain.schemas import SchemaService`.
- Временные/legacy реализации располагаются в `_tmp` или `legacy.py`, с описанием статуса и планом миграции.
- Документацию по модулю добавляем в docstring или `README.md` внутри директории при необходимости.

## Расширение функциональности

1. Добавить доменный сервис либо методы в существующий, сохраняя инварианты.
2. При необходимости обновить инфраструктурный адаптер.
3. Создать/обновить DTO и роутеры.
4. Обновить документацию и тесты.
