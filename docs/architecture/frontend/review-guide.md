# Руководство по ревью фронтенд-кода

> Цель документа — помочь держать архитектурные «рельсы» в актуальном состоянии. Используйте его как чеклист при ревью PR и при самостоятельной проверке изменений.

## 1. Быстрый старт

1. **Определите слой изменяемого файла.**
   - `app/*` — маршруты, компоновка.
   - `components/*` — переиспользуемый UI.
   - `features/<feature>/*` — функциональные блоки (см. структуру ниже).
2. **Проверьте, что изменения лежат в правильном слое.**
   - Бизнес-логика и сетевые вызовы должны располагаться в `features/<feature>/core` и `features/<feature>/adapters` соответственно.
   - React-обвязка (хуки, контексты, страницы) — в `features/<feature>/runtime`.
   - UI — в `features/<feature>/components`.
3. **Сверьтесь с фасадами.** Внешние импорты должны идти через `features/<feature>/index.ts`.

## 2. Проверки по «рельсам»

| Рельс | Вопросы к ревьюеру | Где смотреть |
| --- | --- | --- |
| HTTP-адаптеры | • Все сетевые вызовы вынесены в `adapters`?<br>• Используется `@/lib/api` и типы ответов?<br>• Ошибки нормализуются через `toHttpError`? | `features/<feature>/adapters` |
| Обработка HTTP-ошибок | • Использует ли код `@/lib/api/errors`?<br>• Пробрасываются ли статусы и детали в UI?<br>• Нет ли дублирующих `toError`? | `lib/api/errors`, adapters |
| Runtime-слой | • Компоненты не ходят напрямую к API?<br>• Хуки используют `react-query` (`useQuery`/`useMutation`)?<br>• Ключи запросов описаны как константы? | `features/<feature>/runtime` |
| UI-компоненты | • Нет сетевых вызовов и глобального состояния?<br>• Пропсы типизированы и документированы? | `features/<feature>/components` |
| Фасады | • Экспортируются только публичные сущности?<br>• Нет «проброса» внутренних деталей? | `features/<feature>/index.ts` |
| Импорт | • Применяется алиас `@` вместо `../..`?<br>• Соблюдены ограничения ESLint (`no-restricted-imports`, `boundaries`)? | Все файлы |
| I18n | • Используется `I18nProvider`/`useTranslation` для пользовательских строк?<br>• Есть fallback на ключ?<br>• Локализация не «потеряна» при передаче пропсов? | `lib/i18n`, runtime |
| Контроллеры таблиц | • Табличные страницы используют `useTableController` вместо локального стейта?<br>• Видимость/пагинация/сортировка не дублируется?<br>• Хук подключён в UI-слое? | `lib/ui/table`, `components/ui/data-table` |

## 3. Чеклист перед merge

- [ ] Прошёл `npm run build` (и `npm run lint`, если добавлен в CI).
- [ ] В changelog/описании PR указано, какие рельсы затронуты.
- [ ] Документация (архитектурная карта, справочники) обновлена, если рельсы влияют на структуру фичи.
- [ ] Для новых API/контрактов добавлены типы и описание в `core`.
- [ ] Нет временных заглушек и оставленных `TODO` без задачи в backlog.

## 4. Советы само-проверки для автора

1. **"Импортный тест"** — закомментируйте фасад и убедитесь, что внешние слои не тянут ничего лишнего.
2. **"Визуальный тест"** — просмотрите структуру директории фичи: `adapters → core → runtime → components`. Любая “дырка” — повод перепроверить.
3. **"Ключи запросов"** — убедитесь, что ключи `react-query` объявлены централизованно, не создаются inline.

## 5. Запланированные доработки

- Автоматическая генерация раздела «Структура обзора» (под вопросом, обсуждается отдельно).
- Расширение правил ESLint по слоям после полного перевода фич на новые рельсы.

> После внедрения рельсов в очередную фичу обновите и архитектурную карту, и данный документ (раздел 5).
