# Инфраструктура и деплой

## Обзор

Инфраструктура проекта строится вокруг Docker Compose и GitHub Actions. Основные сервисы:

- **Backend (FastAPI)** — контейнер `app`.
- **Frontend (Vite/React)** — контейнер `frontend` или статическая сборка для CDN.
- **PostgreSQL** — основная база данных.
- **MinIO** — S3-совместимое файловое хранилище.
- Дополнительные сервисы (очереди, кеш) подключаются по мере необходимости.

## Окружения

1. **Локальное** — запуск через `docker compose up`. Использует `.env`/`.env.example`.
2. **Staging** — зеркалирует прод, но с тестовыми данными. Автоматический деплой после успешного CI.
3. **Production** — управляется отдельно (k8s или docker swarm, уточнить). Требует ручного подтверждения деплоя.

## Конфигурация

- Файлы в `config/` содержат параметры для окружений, шаблоны конфигов и секретов.
- Переменные окружения описаны в `config/environments/*.md` ( добавить при необходимости ).
- Настройки логирования и мониторинга фиксируются в этом документе и в `config/`.

## Деплой

1. **Backend**
   - Сборка Docker-образа из `Dockerfile`.
   - Миграции Alembic выполняются автоматически (`alembic upgrade head`).
   - Используется gunicorn/uvicorn.

2. **Frontend**
   - Сборка `npm run build`.
   - Артефакт деплоится в S3/CDN или статический хостинг.

3. **Infra scripts**
   - `init-minio.ps1` — инициализация бакетов и политик.
   - Скрипты миграций и загрузки данных размещаются в `scripts/` (добавить при расширении).

## Мониторинг и логи

- Backend: структурированные логи через `logging`/`structlog` (уточнить текущую реализацию).
- Интеграция с Prometheus/Grafana (планируется/актуально — описать).
- Ошибки собираются через Sentry (если используется).

## Резервное копирование

- PostgreSQL: регулярные дампы (cron/CI job).
- MinIO: репликация или периодические бэкапы.

## Безопасность

- Секреты хранятся в GitHub Secrets и в защищённых vault.
- Минимизируем права сервисных аккаунтов MinIO и БД.
- Внешние API вызываются через HTTPS, ключи не закладываем в репозиторий.

## План развития

- Перенос локального compose на Kubernetes/Helm (при росте команды).
- Добавление Observability (tracing, metrics).
- Автоматизация smoke-тестов после деплоя.
