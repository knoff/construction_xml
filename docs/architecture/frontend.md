# Frontend

## Обзор

Фронтенд построен на React + TypeScript и организован по фичам. Каждая фича — изолированная подсистема со своим публичным API. Общие принципы: feature-based структура, минимальная связность, переиспользование через `index.ts` и явные адаптеры. Общие элементы не складываются в отдельный `shared/`: если что-то требуется в нескольких зонах, это оформляется как самостоятельная фича или подфича.

## Базовые принципы

- **Фичевая изоляция.** Фичи взаимодействуют только через публичные экспортируемые интерфейсы.
- **Повторяемый шаблон.** Все фичи и подфичи строятся по одной схеме (слои `core`, `runtime`, `components`, `adapters`, `modules`).
- **Публичный фасад.** Любое внешнее использование идёт через `index.ts`, в котором собраны стабильные экспортируемые сущности фичи/подфичи.
- **Переиспользование через фичи.** Общие части выносятся в самостоятельные фичи или модули и подключаются через их публичные API.

## Слои фичи

- **`core/`** — доменная логика, типы, преобразования, не зависящие от React и UI.
- **`runtime/`** — интеграция с приложением: провайдеры, хуки, конфигурирование состояний.
- **`components/`** — визуальные компоненты, опирающиеся на данные из `core/` и провайдеров `runtime/`.
- **`adapters/`** — точки расширения и интеграции с другими фичами или внешними сервисами (включая сетевые вызовы).
- **`modules/`** — подфичи (subfeatures), повторяющие ту же структуру для сложных областей.

Каждый слой может отсутствовать, если не нужен конкретной фиче, но при его появлении необходимо соблюдать ответственность и границы зависимостей.

## Обязательные элементы

- **`core/`** — присутствует всегда, так как в нём описываются доменные сущности и типы, составляющие смысл фичи.
- **`index.ts`** — обязательный фасад, который экспортирует публичный API фичи/подфич. Появляется на каждом уровне вложенности.
- **`runtime/`** — обязателен, если фича содержит React-компоненты. Через него прокладываются провайдеры/хуки, к которым подключаются `components/`.
- **`components/`** — опциональны, но если присутствуют, они зависят от `core/` и `runtime/` (минимум от одного). В чисто доменных фичах каталог можно не создавать.
- **`adapters/`, `modules/`** — добавляются по мере появления интеграций и вложенных подфич.

## Публичные API

- На каждом уровне (`feature`, `modules/<subfeature>`) присутствует `index.ts`, формирующий фасад.
- В `index.ts` экспортируются только стабильные сущности, предназначенные для внешнего использования.
- При изменении фасада обновляем документацию и следим за обратной совместимостью.
- Внутренние файлы импортируются напрямую лишь в пределах своей фичи/подфичи.
