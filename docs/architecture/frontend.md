# Frontend

## Обзор

Фронтенд построен на React + TypeScript и организован по фичам. Основные инструменты: Vite, React Router, Zustand/Redux (уточнить фактический стор), Axios для запросов к API.

## Структура каталогов

```
frontend/src/
  features/
    forms/
      valueMapping/
        components/
        store.tsx
        api.ts
  shared/
    components/
    hooks/
    lib/
  app/
    router/
    providers/
  styles/
  assets/
```

### features/

- Каждая фича размещается в отдельной директории с чёткой структурой: `components`, `store`, `api`, `types`.
- Обязательный `index.ts` для экспорта публичного API фичи.
- Локальное состояние хранится в `store` (обычно Zustand). Внутренние типы определяются в `types.ts` либо рядом.

### shared/

- **components** — переиспользуемые UI-блоки.
- **hooks** — общие React-хуки.
- **lib** — утилиты, форматтеры, API-клиент (axios instance).

### app/

- **router** — конфигурация маршрутов.
- **providers** — корневые контексты (темы, i18n, store).

## Принципы

- **Фичевая изоляция.** Фича не импортирует приватные части другой фичи, только публичные.
- **Типобезопасность.** Все API типизированы, внешние DTO адаптируются через мапперы.
- **Слои UI.** Разделяем dumb-компоненты, контейнеры и страницы.
- **Совместимость.** При изменении API обновляем мапперы и тесты.

## Работа с API

- API-клиент объявлен в `src/lib/api.ts`.
- Каждая фича содержит `api.ts` с функциями запросов и мапперами (`map*`), преобразующими серверные структуры во внутренние типы.
- Ошибки обрабатываются на уровне `store`, чтобы UI получал единый формат.

## Стили

- Tailwind или CSS Modules (уточнить текущий подход). Классы собираются через вспомогательные функции (`cn`).
- Общие токены хранятся в `styles/` или config.

## Тестирование

- Unit и компонентные тесты размещаются рядом с компонентами (`*.test.tsx`).
- Для сложных сценариев используются story-based тесты (Storybook) и визуальные сравнения.

## Расширение функциональности

1. Сгенерировать новый фича-пакет через шаблон (если имеется).
2. Определить публичный API фичи (`index.ts`).
3. Добавить мапперы и типы для взаимодействия с backend.
4. Обновить документы в `docs/architecture/frontend.md` и `docs/testing/frontend.md`.
