# Архитектура проекта

Архитектура Construction XML Service разделена на слои, которые соответствуют компетенциям команды и зонам ответственности. Такой подход позволяет развивать backend, frontend и инфраструктуру независимо, не нарушая общие правила API и данных.

## Слои

1. **Backend** — доменные модели, бизнес-логика, интеграции с хранилищами.
2. **Frontend** — пользовательский интерфейс, работа с API, управление состоянием.
3. **Инфраструктура** — окружения, деплой, внешние сервисы (БД, S3, очереди).
4. **Данные** — схема базы, миграции, договорённости по моделированию данных.

## Общие принципы

- **Чёткие границы.** Каждый слой использует публичные интерфейсы соседних слоёв и не обращается к внутренним деталям напрямую.
- **Явные контракты.** API, DTO и схемы данных фиксируются в документации и тестах.
- **Расширяемость.** Новые модули строятся по существующим шаблонам.
- **Обратная совместимость.** Изменения не ломают клиентов, пока не запланирован переход.
