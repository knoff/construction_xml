# CI/CD и матрица прогонов

## Цели

- Гарантировать, что изменения не ломают сборку.
- Автоматизировать тестирование и деплой на всех этапах.
- Минимизировать время обратной связи.

## GitHub Actions

Основные workflows (примерная структура):

1. **`ci.yml`** — базовая проверка PR
   - Установка зависимостей.
   - Линтинг (backend, frontend).
   - Unit-тесты backend (`pytest -m unit`) и frontend (`npm run test:unit`).
   - Отчёт о покрытии.

2. **`integration.yml`** — интеграционные проверки
   - Поднимает сервисы через docker-compose.
   - Запускает интеграционные тесты backend (`pytest -m integration`).
   - Прогоняет frontend интеграции с `msw`.

3. **`e2e.yml`** — сквозные тесты (по расписанию или по кнопке)
   - Разворачивает staging-окружение.
   - Запускает Playwright/Cypress.
   - Сохраняет артефакты (скриншоты, видео).

4. **`deploy.yml`** — деплой
   - Запускается вручную или после успешного merge.
   - Включает smoke-тесты после выката.

## Матрица прогонов

- Backend тестируется на Python 3.11 (в будущем добавим 3.12).
- Frontend — Node LTS.
- Интеграционные тесты запускаются с последними версиями PostgreSQL и MinIO.

## Отчётность

- Все workflow публикуют статусы в PR.
- Отчёты о покрытии — в виде комментариев или в Codecov/Sonar.
- Ошибки e2e сопровождаются ссылками на артефакты.

## Политика merge

- Merge возможен только при зелёном `ci.yml` и `integration.yml`.
- `e2e.yml` может быть необязательным для мелких PR, но обязателен перед релизом.
- Деплой на прод требует ручного подтверждения.

## Будущие улучшения

- Кеширование зависимостей для ускорения сборки.
- Параллельный запуск тестов (sharding).
- Автооткаты при неуспешном smoke-тесте.
