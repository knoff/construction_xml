# Сквозные сценарии (E2E)

## Цели

- Проверить пользовательские сценарии: от входа до формирования документов и связей.
- Валидировать взаимодействие фронта и бэка на реальных данных.
- Обеспечить уверенность перед релизом и после деплоя.

## Инструменты

- **Playwright** или **Cypress** — автоматизация браузера.
- Фреймворк выбирается по доступности команды; ниже примеры на Playwright.

## Окружение

- E2E запускаются против staging-окружения или локального compose с полным набором сервисов (Backend + Frontend + PostgreSQL + MinIO).
- Перед запуском выполняется подготовка данных: миграции, загрузка фикстур, очистка очередей.

## Структура тестов

```
/tests/e2e/
  playwright.config.ts
  fixtures/
  scenarios/
    value-links.spec.ts
    document-fill.spec.ts
```

- `fixtures/` — аккаунты, подготовленные схемы/документы.
- `scenarios/` — tests, описанные в терминах бизнес-шагов.

## Подход

1. **Arrange** — очистить и подготовить состояние (API, SQL скрипты).
2. **Act** — пройти сценарий в браузере (логин, выбор документов, создание связей).
3. **Assert** — проверка UI и состояния в БД через API (если нужно).

## Стабильность

- Используем явные ожидания (wait for selectors).
- Минимизируем зависимость от анимаций и случайнно генерируемых данных.
- Скриншоты и видео сохраняются как артефакты.

## Регламент

- E2E проходят на nightly-сборке или перед релизом.
- Критичные сценарии (поддержка связи value-links, создание документа) гоняются перед деплоем на прод.
- Отчёты публикуются в Slack/Telegram (настроить алерты).
