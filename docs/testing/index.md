# Стратегия тестирования

Документ описывает общие цели и подходы к тестированию проекта. Подробности по конкретным слоям вынесены в дочерние разделы.

## Цели

1. **Надёжность.** Обнаруживать регрессии до выката в прод.
2. **Повторяемость.** Тесты должны стабильно проходить в локальной среде и в CI.
3. **Полнота.** Покрываем все ключевые сценарии: backend, frontend, интеграции, деплой.
4. **Прозрачность.** Результаты тестов доступны в CI и фиксируются в отчётах.

## Пирамида тестирования

1. Unit-тесты — быстрые проверки функций, сервисов, компонентов.
2. Интеграционные — взаимодействие модулей и API.
3. Сквозные (E2E) — пользовательские сценарии в реальном окружении.
4. Smoke — проверки после деплоя.

## Обязанности

- **Разработчики** пишут юнит и интеграционные тесты при изменении кода.
- **QA/DevOps** отвечают за e2e и smoke, но разработчики участвуют в поддержке сценариев.

## Регламенты

- Любая новая функциональность сопровождается тестами на своем уровне.
- Рефакторинг должен сохранять существующие тесты либо обновлять их.
- Красный тест — блокер для merge.
