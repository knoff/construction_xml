# Тестирование frontend

## Цели

- Проверить корректность UI-компонентов и состояний.
- Гарантировать соответствие интеграции с backend-клиентами.
- Предотвратить регрессии в пользовательских сценариях.

## Типы тестов

1. **Unit/Component**
   - Расположение: `frontend/src/**/__tests__/` или `*.test.tsx` рядом с компонентом.
   - Используем React Testing Library + Jest/Vitest.
   - Тесты проверяют рендеринг, взаимодействие, обработку пропсов и стейта.

2. **Store/Hook**
   - Тестируются состояния (Zustand/Redux) и кастомные хуки.
   - Моки API-клиента через `jest.mock` или `msw`.

3. **Story-based**
   - Storybook stories выступают как документация и тесты визуального состояния.
   - Для критичных компонентов делаем снапшоты (`@storybook/testing-react`) или визуальные сравнения (Chromatic, Loki).

4. **Интеграционные**
   - Проверяют связку компонентов, роута и API-клиента.
   - Используют `msw` для моков backend.

## Организация

- `vitest.config.ts`/`jest.config.js` содержит общие настройки.
- Общие утилиты тестирования (рендер с провайдерами) — в `frontend/src/test-utils`.
- Все тесты запускаются командой `npm run test`.

## API и моки

- Для HTTP-запросов используем `msw` (Mock Service Worker), сигнатуры соответствуют руководству по API.
- При изменении контрактов обновляем моки и проверяем, что фронтенд корректно обрабатывает новые поля.

## Покрытие

- Покрытие ключевых фич — ≥70% строк (минимум, уточнить по политикам).
- Критические компоненты (`MappingDialog`, `FieldTreePanel`, `SearchResultsPanel`) тестируются на рендеринг и обработку пользовательских действий.

## Требования к PR

- Новые компоненты — обязателен unit-тест.
- Изменения в сторе — тесты на редьюсеры/экшены.
- UI-изменения — обновление стори и визуальной регрессии (если подключена).

## Интеграция с CI

- Команда `npm run test -- --runInBand`/`pnpm test` (уточнить) запускается в GitHub Actions.
- В случае визуальных тестов результаты крепятся к PR.
